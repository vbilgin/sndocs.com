# CLAUDE.md

Guidance for working in this repository.

## What this project is

A Python CLI (`sndocs`) that fetches the ServiceNowDocs Markdown corpus,
normalizes it, and builds a static docs site with MkDocs + Material for
MkDocs, served locally. See README.md for the full pipeline description.

## Ground rules

- **This repo is code/config only.** Never commit generated artifacts:
  cloned source, normalized Markdown, or built site output. All of that
  lives under `.sndocs/` (gitignored).
- **No GitHub Actions / CI automation.** This repo intentionally has none —
  don't add workflow files.
- **No release/hosting concerns here.** Deploying to sndocs.com is explicitly
  out of scope for v1. Don't add deployment tooling unless asked.
- **v1 targets the `australia` branch only.** Don't add multi-version
  support unless explicitly requested.
- **Full rebuild by default.** The pipeline (`fetch` → `normalize` → `build`)
  is designed to always run end-to-end; don't add incremental/change-detection
  complexity unless asked.

## Architecture notes

- `sndocs serve` serves the static output of `.sndocs/site/` directly (not
  `mkdocs serve`) — it must never trigger its own build or watch files. If
  the site looks stale, the fix is to re-run `sndocs build`, not to make
  `serve` smarter.
- Search is Pagefind, run as a **post-build** step over the MkDocs output
  (Pagefind has no native Python API — it's invoked as a CLI subprocess).
  Material's built-in search plugin must stay disabled; don't re-enable it
  alongside Pagefind.
- Nav is auto-generated by mirroring the source `markdown/<category>/...`
  directory structure. Don't hand-author `nav:` entries in `mkdocs.yml`.
- Link rewriting is intentionally narrow: only rewrite links matching the
  known raw-GitHub `.md` URL pattern where the target exists in the corpus.
  Don't expand this into general link resolution.
- The Markdown normalizer's "safe to clean up" checks must be validated
  against the actual rendering engine in use (MkDocs' Python-Markdown, via
  Material's `pymdownx` extensions) — not assumed equivalent to an earlier
  `markdown-it-py`-based validation pass.

## Testing

- `pytest` covers the CLI's own logic: link rewriting, nav generation,
  commands.
- The normalizer's correctness is validated separately via its own
  invariants and `normalization-report.json` — don't duplicate that in
  pytest; extend the normalizer's own checks instead if you find a gap there.
