# sndocs.com

A Python CLI that turns the [ServiceNow/ServiceNowDocs](https://github.com/ServiceNow/ServiceNowDocs)
Markdown corpus (`australia` branch, ~24k files) into a locally-served static
docs site, built with MkDocs and Material for MkDocs.

This repository holds code and config only. It does not house releases,
CI/CD automation, or generated output.

## What it does

1. **fetch** — shallow-clones/pulls the `australia` branch of ServiceNowDocs
   into `.sndocs/repo/`.
2. **normalize** — cleans and canonicalizes the Markdown (YAML front matter,
   HTML tables, fences, escapes) into `.sndocs/normalized/`, and rewrites
   internal links that point at raw GitHub `.md` URLs into relative links
   where the target exists in the corpus.
3. **build** — feeds normalized Markdown into MkDocs/Material as `docs_dir`,
   with nav auto-generated by mirroring the source directory tree, then runs
   [Pagefind](https://pagefind.app/) over the built site to generate a search
   index. Output lands in `.sndocs/site/`.
4. **serve** — serves `.sndocs/site/` on localhost with a plain static file
   server (not `mkdocs serve`), so what you see is exactly what `build`
   produced.
5. **all** — runs fetch → normalize → build end-to-end.

Every run is a full rebuild; there's no incremental/change-tracking in v1.

## Usage

```bash
pipx install .
sndocs all
sndocs serve
```

Or run steps individually: `sndocs fetch`, `sndocs normalize`, `sndocs build`,
`sndocs serve`.

## Scope

- Targets only the current release branch (`australia`) — no multi-version
  switcher.
- Hosting/deploying the built site to sndocs.com is out of scope for v1; the
  end result is a static site served on localhost.
- Search UI uses Pagefind's default `pagefind-ui` widget, not a custom modal.
- Front matter beyond `title` (`product_area`, `canonical_url`, `breadcrumb`,
  etc.) is preserved in the normalized Markdown but not surfaced in the site.

## Development

```bash
pip install -e ".[dev]"
pytest
```

The test suite covers the CLI's own logic (link rewriting, nav generation,
commands). The Markdown normalizer's correctness is validated separately via
its own invariant checks and report, generated at `.sndocs/normalized/normalization-report.json`.
